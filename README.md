# NEXT × 테르밋 — 실사 근거를 활용한 제품 일관성 설계

**실제 상품 사진이 있는데, 왜 광고를 만들 때마다 제품까지 다시 그려야 할까?**

AI 광고에서 제품의 형태·비율·부품 연결·로고가 달라지는 문제를 다룬 기업과제다. 처음에는 생성 순서와 참조 방식을 바꾸었고, 이후 **제품의 사실은 실사에서 가져오고 광고 연출은 생성 모델에 맡기는 제작 방식**을 설계했다.

VFX의 실사 재투영, 컴파일러의 불변조건, 카메라 계획, 소프트웨어 검증에서 아이디어를 가져왔다. 이를 실사 재투영 렌더러, 구도 선택 코드, 인쇄 복원 웹 시제품, 부품 합성, 3D 자산 검사, 상품별 LoRA 학습·비교로 구체화했다. 팀원의 기준 자료 구성·검수·실물 복원 코드도 함께 담았다.

이 저장소의 산출물은 **제작 방식의 청사진과 이를 검증한 실험 코드·시제품**이다. 큰 인쇄의 자동 배치와 일부 원본 정보 보존은 확인했다. 새로운 시점의 전체 구조와 자연스러운 합성, 일반 생성 대비 일관된 품질 우위는 남은 문제다.


**테르밋에 제안하는 방향은 제품과 요청에 따라 참조 생성·상품 학습·직접 보존·부분 복원을 선택하는 제작 방식이다.** 아래 실험은 이 선택을 설계할 근거를 제공한다. 자동으로 최적 경로를 고르는 기능이나 서비스 효과는 아직 검증하지 않았다. [테르밋에 제안하는 방향과 검증 순서](#termit-proposals)에서 확인된 결과와 후속 가설을 나눠 설명한다.

## 1. 다른 분야의 아이디어를 광고 제작에 옮기다

초기 실험에서 단계 분리나 원본 재참조만으로는 안정적인 추가 효과를 얻지 못했다. 잘못된 중간 제품 컷을 다음 단계가 그대로 이어받기도 했다. 그래서 “더 정확하게 그리도록 지시하기”에서 **“이미 확인한 제품 정보를 어떻게 제작 과정에 남길 것인가”**로 질문을 바꾸었다.

각 분야의 아이디어를 제품 보존 문제에 맞게 옮기고, 설계 관점과 실제 구현 범위를 구분했다.

| 영감을 얻은 분야 | 광고 제작에 옮긴 아이디어 | 실제 구현과 경계 |
|---|---|---|
| **VFX · 컴퓨터 그래픽스** — Image-Based Rendering | 사진 속 제품을 매번 재생성하는 대신, 원본 픽셀을 목표 카메라로 옮긴다 | 원통·박스 근사 형상, 면별 Homography, 원본 좌표·미관측 영역 기록. 정확한 임의 형상 복원까지 구현한 것은 아님 |
| **컴파일러 · 제약조건** — 중간 표현(IR), 불변조건 | 제품명·형태·부품 관계와 배경·조명·연출을 분리하고, 보존 조건을 제작 단계에 전달한다 | 우리 측 상태·검수 조건과 팀원의 `refset`·`spec`으로 일부 구체화. 범용 제품 IR과 자동 제작 경로 선택기는 청사진 |
| **최적화 · 카메라 계획** — 제약 안에서 후보 선택 | 모든 구도를 똑같이 생성하기보다, 허용된 구도 중 확보한 실사로 표현하기 유리한 구도를 고른다 | 관측 범위·투영 왜곡·구조 불일치 점수로 정답을 보기 전에 구도 선택. 선택 코드의 품질 개선 효과는 확인하지 못함 |
| **소프트웨어 검증 · 복원** — 불변조건 검사, 출처 추적, 보류 | 잘못된 부분만 원본으로 복원하고, 대응 근거가 부족하면 덮어쓰지 않는다 | SIFT/RANSAC 정렬, 편집 영역 밖 픽셀 확인, 배치·유지·보류. 모든 구조 오류를 자동 판정하는 검수기는 미구현 |

## 2. 설계한 제작 방식: 제품의 사실과 광고 연출을 분리한다

```text
실제 상품 사진 + 광고 요청
          ↓
제품에서 유지할 사실 / 바꿀 수 있는 연출 분리
          ↓
사용할 실사·허용 구도·제작 경로 선택
          ↓
실사 재투영 · 원본 부품/인쇄 재사용 + 장면 생성
          ↓
제품 조건과 합성 상태 확인 → 필요한 부분 복원 / 근거 부족 시 보류
```

**위 흐름은 전체 설계다.** 아래 구현물은 각 연결 고리를 시험한 독립 코드이며, 사진과 요청만 넣으면 완성 광고를 내는 통합 엔진으로 연결된 상태는 아니다. 3D 자산과 상품별 LoRA는 실사 재투영·2D 합성의 구조 한계를 보완할 수 있는 별도 경로로 시험했다.

팀원 작업은 이 설계의 앞단인 **기준 자료·제작 명세**와 뒷단인 **검수·국소 복원**을 탐색했다. 우리 측 재투영·구도 선택 실험과 함께 읽으면, 제품 정보를 입력에서 정리하는 문제부터 장면에 배치하고 다시 확인하는 문제까지 볼 수 있다.

### 제품 정보를 어디에 유지할 것인가

실험을 돌아보면 제품 정보를 사용하는 방식을 다음 네 경로로 정리할 수 있다. **이는 결과를 종합한 분류이며, 처음부터 네 경로를 동일 상품·모델·장면으로 통제 비교한 실험은 아니다.** 부분 복원은 직접 사용과 겹칠 수 있으며, 무엇을 얼마나 유지할지에 초점을 둔 경로다.

| 경로 | 제품 정보가 결과에 반영되는 방식 | 이번에 실행한 범위 |
|---|---|---|
| **참조 후 생성** | 실사·제품 시트를 입력으로 제공하고 모델이 제품을 다시 생성 | Run 09–11의 참조 조건 비교, Run 31 일반 호출의 실사 12장·참조 보드 3개. 시트 배치 방식 자체의 효과는 미검증 |
| **상품별 학습** | 제품 사진의 정보를 추가 가중치에 반영하고 생성 | Run 31 SDXL LoRA 학습·전후 비교 완료. 해당 설정의 품질 우위 미확인 |
| **직접 보존** | 실제 사진 또는 3D 렌더를 최종 제품 표현에 사용 | 실사 재투영과 제품 레이어 고정 합성 실행. Run 30은 3D 자산 검사에서 중단해 완성 광고 비교는 미실행 |
| **부분 복원** | 생성된 장면을 유지하면서 특정 인쇄·부품을 원본 정보로 교체 | JamMate 인쇄, 우리 측 펜·골프티 및 팀원 부품·인쇄 복원. 수동 등록과 상품별 제약 포함 |

이 분류에서 중요한 질문은 **최종 제품을 생성 모델이 다시 그리는지, 원본 정보가 처리 과정에서 직접 유지되는지**다. 정확한 3D 자산이라도 렌더 이미지를 참조로만 주면 재생성 경로이고, 최종 제품 영역에 직접 쓰면 보존 경로다. 이번 과제에서 이 두 3D 활용 방식을 비교한 것은 아니다. 직접 사용하더라도 입력 자산의 결함이나 배치·접촉 오류까지 해결되는 것은 아니다.

## 3. 실제 만든 것: 아이디어를 처리 코드와 시제품으로 옮기다

### 실사 재투영 렌더러와 구도 선택

원본 사진을 근사 형상에 투영하고 목표 카메라에서 렌더링했다. 결과 픽셀이 어느 사진의 어느 위치에서 왔는지 기록하고, 실사에 없는 영역을 드러내도록 했다. 이어 구도 후보를 점수화하고 **제작에 사용하지 않은 목표 시점 사진**으로 평가하는 절차를 만들었다.

- 코드: [원통 재투영](research/experiments/evidence_renderer/run18/render.py), [박스 재투영](research/experiments/evidence_renderer/run19/produce.py), [구도 선택](research/experiments/evidence_renderer/run21/run_selection.py)
- 확인한 것: 실사 정보의 재사용·출처 추적은 구현했다. 박스의 접힘·접합까지 정확히 옮기려면 근사 형상보다 정밀한 기하 정보가 필요했다.

### JamMate 인쇄 복원 모듈과 브라우저 시제품

원본 인쇄 영역을 등록한 뒤 **SIFT 특징점 → RANSAC 기반 평면 변환 → 인쇄 배치**로 광고 속 위치를 찾는다. 충분한 대응 근거가 없거나 인쇄가 너무 작으면 보류하고, 기존 어두운 인쇄가 있으면 유지하도록 했다. 이 처리 흐름을 원본·광고 업로드와 결과 확인이 가능한 웹 시제품으로 옮겼다.

- 코드: [자동 복원](research/experiments/surface_restore/run23/restore.py), [브라우저 처리 엔진](research/sites/jammate-print-lab/dist/assets/engine.py), [웹 소스와 공개본 실행 범위](research/sites/jammate-print-lab/README.md)
- 확인한 것: 의도적으로 제품명을 비운 JamMate 광고에서 기존 등록값으로 큰 인쇄를 자동 배치했다. 원본 등록은 수동이며, 다른 상품에서의 성공이나 제품 전체 구조 보존을 뜻하지 않는다.

### 원본 부품 합성과 팀원의 국소 복원

우리 측은 펜·골프티의 실제 부품을 축·비율·마스크로 정렬하고, 제품 레이어를 고정한 채 주변 장면을 만드는 방식을 시험했다. 팀원은 전체 제품 교체와 함께 **LaMa 기반 제거 후 부품 삽입**, **생성본의 저주파 조명과 원본 인쇄의 고주파 획 결합**을 탐색했다.

- 코드: [펜 부품 배치](research/experiments/structural_restore/run27/produce.py), [제품 선고정 합성](research/experiments/structural_restore/run29/composite.py), [팀원 부품 복원](teammate/creazy-consistency/spikes/validation/showcase_shape.py), [팀원 인쇄 복원](teammate/creazy-consistency/check/print_restore.py)
- 확인한 것: 일부 비율·인쇄 정보를 재사용할 수 있었다. 전체 제품을 유지해도 조명·반사·가림·접촉이 맞지 않으면 합성감이 남았다. 작은 부분의 복원이 유리할 수 있다는 관찰은 제한된 사례의 가설이다.

### 3D 자산 검사와 상품별 LoRA 학습·비교

2D 조각만으로 구조를 고정하기 어려워, 실제 3D 형상을 쓰거나 상품 정보를 모델에 학습시키는 경로도 구현했다. 3D에서는 OBJ 면·UV를 보존하는 로더를 보완하고 두 구도를 검사했다. LoRA에서는 **SDXL UNet attention adapter, rank 4, 실사 12장, 200 steps**로 M5 GPU 학습을 실행하고 학습 전·후·일반 호출을 비교했다.

- 코드: [3D 검사 렌더](research/experiments/asset_renderer/run30/render.py), [LoRA 학습](research/experiments/product_lora/run31/train.py), [LoRA 추론](research/experiments/product_lora/run31/infer.py)
- 확인한 것: 3D는 자산 품질 기준을 통과하지 못해 광고 비교까지 진행하지 않았다. LoRA는 학습·비교까지 완료했지만 해당 설정의 품질 우위를 얻지 못했다. 더 많은 GPU 자원이나 학습량의 효과는 별도 검증이 필요하다.

### 기준 자료·명세·검수와 비교 실험 도구

팀원은 상품 사진을 기준 세트로 정리하는 `refset`, 보존 조건과 광고 요청을 구성하는 `spec`, 검수·수정·복원을 담당하는 `check`, FastAPI 데모를 만들었다. 우리 측은 생성 조건 구성, 요청 계획·예산, 실행 재개, 검수·후속 편집을 비교할 도구를 작성했다.

- 코드: [팀원 기준 세트](teammate/creazy-consistency/refset/build.py), [제작 명세](teammate/creazy-consistency/spec/make.py), [검수](teammate/creazy-consistency/check/run.py), [API 실험 실행기](research/experiments/product_view_api/run_api.py)
- 확인한 것: 입력과 처리 조건을 명시적으로 다루는 도구다. 구조화된 절차 자체가 일반 호출보다 좋은 결과를 보장하지는 않았다.

## 4. 두 작업을 통해 구체화한 설계 판단

**재사용할 정보와 새로 풀어야 할 문제를 구분하게 됐다.** 원본 인쇄·부품 내부의 정보는 가져올 수 있지만, 새로운 시점의 위치·가림·연결 관계는 별도의 기하 문제였다. 우리 측 재투영의 접합 오차와 팀원 전체 합성의 부자연스러움은 이 경계를 서로 다른 조건에서 보여준다.

**복원의 단위도 설계 변수였다.** 제품 전체를 교체하면 보존할 수 있는 원본 정보는 많지만 장면과 맞춰야 할 경계도 넓어진다. 팀원의 부분 복원과 우리 측 인쇄 시제품은 국소 처리의 가능성을 보였다. 다만 상품과 평가 조건이 달라 “작게 고치면 항상 낫다”는 결론은 내리지 않았다.

**기능이 작동하는지와 그 기능을 추가할 이유가 있는지를 따로 평가했다.** 자동 배치·픽셀 보존·학습 완료를 확인한 뒤에도 일반 생성과 비교했다. 이 구분 덕분에 작동하는 모듈은 남기면서, 추가 품질 효과를 얻지 못한 경로는 중단할 수 있었다.

세부 비교는 [팀원 작업과 통합 인사이트](docs/team-integration.md)에 정리했다. 아래 실험 기록에는 이 판단에 이르기까지의 조건, 결과, 수치와 미검증 범위를 남겼다.

## 5. 테르밋에 제안하는 방향과 검증 순서

제안의 중심은 **제품 전체를 매번 다시 생성하는 대신, 생성할 영역과 보존할 영역을 선택하는 광고 제작**이다. 아래의 ‘확인한 근거’는 기존 실험 결과이고, ‘제안’은 이를 바탕으로 검토할 가설이다. **제안의 효과, 자동 경로 선택, 고객 승인·비용 개선은 아직 검증하지 않았다.**

### 제안 A. 실사 기반 제품 시트를 입력 구성의 비교 기준으로 삼는다

- **확인한 근거:** Run 09에서 목표 측면 실사를 추가했을 때 주요 측면 디자인이 더 가까워졌다. Run 31에서는 동일 실사 12장을 참조 보드 3개로 제공한 일반 생성이 시험한 LoRA보다 주요 형태를 잘 유지했다. 다만 후자의 기반 모델과 입력 방식은 서로 달랐다.
- **제안·미검증 가설:** 캐릭터 시트처럼 전체 시점과 식별 부품을 정리한 제품 시트가 참조 정보의 전달을 개선하는지 확인한다. 실사로 구성하며, AI가 만들어낸 미관측 면을 확인된 원본 정보와 섞지 않는다.
- **검증할 비교:** 같은 원본 사진·광고 요청·생성 모델로 개별 사진 입력과 시트 입력을 비교한다. 사진 선정과 시트 배치 효과는 따로 시험하고, 축소로 인한 디테일 손실도 확인한다. Run 31만으로 시트 구성이 효과적이었다고 결론 내리지 않는다.

### 제안 B. 복원할 수 있는 오류의 범위를 먼저 정한다

- **확인한 근거:** JamMate의 큰 인쇄는 제한된 통제 사례에서 자동 배치됐다. 다른 상품은 대응점 부족으로 보류했다. 팀원 부품·인쇄 복원은 일부 가능성을 보였지만, 전체 교체와 우리 측 골프티 합성에는 자연스러움 문제가 남았다.
- **제안·미검증 가설:** 인쇄 누락처럼 위치와 원본 근거를 확보할 수 있는 오류부터 부분 복원의 적용 범위를 정의한다. 부품 구조 오류와 인쇄 오류는 별도 평가한다. 작은 복원이 항상 유리하다는 전제는 두지 않는다.
- **검증할 비교:** 같은 오류가 있는 생성본에서 일반 재생성과 국소 복원을 비교한다. 제품 정확성, 영역 밖 변경, 합성 자연스러움, 등록·수정 시간을 따로 기록한다. 보류한 결과는 복원 성공으로 세지 않는다.

### 제안 C. 제품·요청에 맞는 제작 경로를 선택한다

- **확인한 근거:** 실사 재투영에서는 접힘·접합의 구조 오차가, 원본 고정 합성에서는 경계·접촉의 합성감이 나타났다. LoRA는 학습을 완료했지만 해당 설정의 품질 우위를 얻지 못했다. 경로마다 다른 병목이 있었다.
- **제안·미검증 가설:** 요청 구도, 보유 실사·자산, 보존할 부품, 허용 연출을 기준으로 참조 생성·학습·직접 보존·부분 복원 중 적용할 경로를 선택한다. 이 자동 선택기는 미구현이다. 먼저 사람이 적용 조건과 결과를 기록하는 비교부터 설계한다.
- **검증할 비교:** 동일 상품·장면에서 실행 가능한 경로를 비교하고, 선택 규칙은 별도 상품에서도 평가한다. 고객이 허용한 경우에만 구도 변경을 후보에 넣는다. 3D 경로는 실제 제품과 일치하고 품질 기준을 통과한 자산이 있어야 비교에 진입한다.

### 제안 D. 실제 서비스 조건에서 품질과 사용 가능성을 분리해 평가한다

- **확인한 근거:** 여러 실험에서 일반 호출도 기준을 통과했다. 크리에이지 내부의 실제 입력 목록·생성 설정은 확보하지 못했고, 고객 승인·반복 수정·총비용의 운영 비교도 하지 못했다.
- **제안·미검증 가설:** 현재 서비스의 제작 흐름을 기준선으로 두고 위 방법의 추가 효과를 판단한다. 제품 정확성, 광고 자연스러움, 고객 사용 가능성은 서로 다른 평가 항목으로 유지한다.
- **검증할 비교:** 동일 요청과 자료로 기준선·후보 방식을 반복 실행하고, 가능한 경우 방식 이름을 가린 평가를 한다. 원본 등록·학습·자산 준비를 포함한 총작업량과 비용, 수정 횟수, 고객 승인 여부를 기록한다. 일부 기능의 통과를 전체 광고의 승인으로 대체하지 않는다.

**제안하는 검증 순서:** 먼저 D의 서비스 기준선과 평가 항목을 확보하고, A의 입력 구성 및 B의 제한된 복원을 비교한다. 그 결과를 모아 C의 경로 선택 규칙을 검토한다. 이는 효과가 입증된 우선순위가 아니라, 입력·개입 범위를 먼저 좁혀 추가 처리의 가치를 판별하기 위한 제안이다.

**3D·LoRA의 다음 가능성은 조건부로 남긴다.** 이번 자산과 학습 설정의 추가 작업은 중단했으며, 이 문서가 실험 재개를 뜻하지는 않는다. 정확한 3D 자산이나 다른 기반 모델·학습 데이터가 확보된 조건의 효과는 별도 질문이다. GPU·API 자원이 늘어나는 것만으로 구조 보존이 해결된다고 약속하지 않는다.

# 실험 과정 상세

아래는 2026-11-18, Run 31 종료 시점의 보고서를 공개용으로 정리한 기록이다. 수치는 각 실험의 조건 안에서만 해석한다. 서로 다른 모델·상품·평가자·버전의 결과를 합산한 성공률은 없다.

## 1. 문제 정의와 설계의 전개

### 출발: 제품을 정확히 그리게 하는 제작 절차가 필요한가

처음에는 각도 변경과 광고 연출을 한 번에 요청하는 것이 제품 변형을 일으킨다고 보고, 제품 컷을 먼저 만든 뒤 광고로 옮기는 방식과 원본을 다시 참조하는 방식을 비교했다. 연속 수정에서 오류가 누적되는지, 원하는 면의 실사 정보가 부족한 것인지도 나누어 살폈다.

초기 실험에서는 일반 호출도 주요 형태를 보존하는 경우가 많았다. 반대로 중간 제품 컷이 이미 틀리면 이후 단계는 그 오류까지 잘 보존했다. 따라서 **단계를 나누거나 지시를 늘리는 것 자체가 개선책은 아니었다.**

### 실제 고객 사례로 확장: 무엇을 보존해야 하는가

고객 문의에서 원본과 결과를 연결할 수 있는 3개 제품의 21장을 검토했다. 제품명 누락뿐 아니라 냄비의 형태·디자인 선택, 마킹펜의 촉과 연결부 변형이 문제였다. 고객이 나중에 선택한 제품 사진과 이전의 잘못된 예시를 구분하는 일도 중요했다.

이 과정에서 원본감을 단순한 픽셀 일치나 모든 작은 글자의 정확성으로 보지 않고, **그 제품이라고 인식하게 하는 큰 형태·부품 관계·주요 디자인과 요청한 시점의 유지**로 구체화했다. 조명 변화나 회전으로 정상적으로 가려지는 로고는 오류와 구분했다.

### 접근 전환: 왜 제품을 다시 그려야 하는가

생성 모델에 정확히 그리라고 지시하는 것에서 벗어나, 실사에서 확보한 정보를 최대한 재사용하는 방향으로 바꾸었다. 핵심 구상은 다음과 같았다.

> 제품의 바뀌면 안 되는 사실과 바꿔도 되는 광고 연출을 분리한다. 실제 사진으로 확인되는 부분은 재사용하고, 부족한 부분만 생성하며, 근거가 부족하거나 제품 조건을 위반하면 수정하거나 보류한다.

이를 위해 VFX의 실사 재투영, 컴파일러의 제약조건 관리, 제어의 원본 재검증, 출처 관리, 소프트웨어 테스트의 불변조건이라는 관점을 검토했다. 이 모두를 통합 구현한 것은 아니다. 실제로 실행한 부분은 근사 형상 재투영, 출처 좌표 기록, 제한된 검사와 보류 등이었다.

### 정확한 생성에서 정확하게 만들 수 있는 구도 선택으로

재투영 결과의 넓은 평면은 비교적 잘 맞아도 모서리·접합부가 틀렸다. 이에 “모든 각도를 정확히 만들기” 대신 **고객이 허용한 구도 중 정확하게 표현할 수 있는 구도를 고르는 것**을 시험했다.

이 가설은 정답 사진을 본 뒤 좋은 결과를 고르는 것으로 검증할 수 없다. 제작에 사용한 사진만으로 구도를 먼저 선택한 다음, 사용하지 않은 목표 시점 실사와 비교하도록 설계했다. 정확한 각도가 필수인 요청을 임의로 쉬운 각도로 바꾸는 것은 허용하지 않았다.

### 표면 복원에서 부품 구조·3D·학습으로 질문을 확장하다

구도 선택이 개선을 만들지 못하자 표면 인쇄 복원으로 범위를 좁혔다. 자동 배치와 보류 기능은 구현했지만, 일반 호출도 제품명을 읽을 수 있게 만들었다. 작은 인쇄를 복원하는 시연만으로는 제품 전체의 원본감 개선을 보여주기 어려웠다.

그래서 대표 사례를 마킹펜과 골프티의 구조 문제로 옮기고, 원본 부품을 재사용했을 때 실제로 차이가 생기는지 비교했다. 부품 비율 일부는 보존됐지만 휘어짐·주변 번짐·이중 윤곽·합성감이 남았다. 이후 제품 형상을 결정할 다른 근거를 찾기 위해 실제 3D 자산과 상품별 학습까지 시험했으나 채택할 품질을 얻지 못했다.

### 단계별 관찰과 판단

각 행은 하나의 가설 묶음이다. ‘차이 없음’은 이번 작은 비교에서 추가 이점을 확인하지 못했다는 뜻이며, 모든 상황에서 효과가 없다는 증명은 아니다.

## 4. 검증을 거치며 실제로 보완한 것은 무엇인가

### 실행·기능 측면에서 고친 것

- **T4의 심한 노이즈:** 이미지 조절 층까지 양자화한 실행 코드 문제를 확인하고 해당 층을 원래 정밀도로 유지해 해소했다. 이후 7장 비교를 실행했다. 제품 형상 보존 성능을 고쳤다는 의미는 아니다.
- **인쇄의 수동 위치 지정:** 원본·광고의 특징점을 대응시키고 평면 변환을 추정해, 광고마다 위치를 손으로 맞추던 절차를 자동 배치로 바꾸었다.
- **불확실한 자동 덮어쓰기:** 대응점 분포, 예상 인쇄 크기, 기존 어두운 인쇄의 존재를 검사해 유지·보류할 수 있게 했다. 문구의 의미나 철자를 판독하는 검수기는 아니다.
- **3D 파일 호환성:** 잘못된 법선 인덱스로 원본 면이 누락되는 로더 문제를 보완했다. 정상적으로 읽은 뒤에도 남은 형상 결함은 고치지 않았다.
- **로컬 학습의 실행 오류:** 입력 자르기 공통 규칙을 두 번 수정했고, SDXL 프롬프트가 길이 제한으로 잘려 두 구도가 같아지던 문제를 수정했다. 잘린 초기 4장은 따로 보관하고 유효 비교에서 제외했다.

### 평가와 적용 범위에서 바꾼 것

- 실사 픽셀을 사용했다는 사실만으로 성공을 판단하지 않고, 제작에 쓰지 않은 목표 사진에서 로고·모서리·접합부를 따로 확인했다.
- 구도 선택은 정답을 열기 전에 고정했다. 평가 후 좋은 각도를 골라 성공으로 보고하지 않았다.
- 일반 비교군에도 같은 핵심 자료와 보존 조건을 제공했다. 복잡한 절차가 간단한 호출보다 나은지 확인하려는 기준을 유지했다.
- 작은 인쇄가 읽히지 않자 시제품 지원 범위를 큰 인쇄로 줄였다. 잠정 15px 보류 기준은 이번 사례용 제한이지 보편적인 가독성 법칙이 아니다.
- 수동 수정 0회라도 합성감이나 구조 오류가 남으면 실패로 처리했다. 무변경 보류도 복원 성공과 구분했다.

이는 **기능 개선, 평가 보완, 지원 범위 축소, 가설 중단**이 섞인 결과다. 모두를 ‘엔진 성능 향상’으로 표현하지 않는다.

## 5. 실험으로 확인한 기술적 병목

### ① 확인된 제품 표현 없이 생성 절차만 바꾼 방법의 한계

단계 분리·상태 관리·상세 프롬프트는 무엇을 해야 하는지 정리하지만, 생성 모델이 그 제품의 형상과 연결 관계를 반드시 따르도록 만들지는 못했다. 잘못된 중간 결과가 다음 단계로 전달되거나, 올바른 계획을 세워도 결과가 달라졌다. 확인된 범위에서는 절차 개선만으로 제품 구조를 강제하기 어려웠다.

### ② 실사 정보의 재사용과 정확한 공간 배치는 다른 문제

원본의 글자나 부품을 가져오면 그 내부 정보는 유지할 수 있다. 그러나 목표 시점에서의 위치·크기·가림·접합까지 맞으려면 정확한 형상과 카메라 관계가 필요하다. 원통·직육면체 근사는 실제 라벨 곡률, 박스의 접힘과 부풀어 오른 면을 표현하지 못했다. 관측된 면적이나 투영 왜곡을 줄이는 구도 점수도 실제 구조 오차를 충분히 설명하지 못했다.

### ③ 정확한 부품 조각이 자연스러운 광고를 보장하지 못함

원본 부품을 고정하면 내부 비율은 보존되지만 조명·반사·해상도·주변 가림과 맞지 않을 수 있다. 골프티에서는 삭제한 영역의 잔디 번짐, 주변 생성 이후 이중 윤곽이 나타났다. 배치 좌표가 정확히 재사용됐다는 검사는 장면의 자연스러움을 보장하지 못했다.

### ④ 일부 실험에서는 일반 호출이 이미 충분히 잘했음

단계 분리·실물 재참조·구조화 검수의 비교에서 일반 방식도 기준을 통과했다. JamMate 직접 생성도 제품명을 읽을 수 있게 만들었고, 골프티도 일반 호출로 핵심 부품을 고쳤다. 따라서 기능이 작동하는 장면을 보여주는 것만으로는 별도 시스템을 사용할 이유가 충분하지 않았다. Run 09의 개선에는 새 측면 정보를 추가한 효과가 포함되므로 자체 처리 방식의 우위로 볼 수 없다.

### ⑤ 검증 가능한 작은 목표로 좁히는 과정에서 대주제와 멀어짐

인쇄 자동 배치, 영역 밖 픽셀 보존, 마킹펜의 특정 길이 비율처럼 측정하기 쉬운 항목에는 진전이 있었다. 그러나 사용자가 문제 삼은 것은 제품 전체가 다른 물건처럼 보이거나 펜이 휘는 현상이었다. 부분 지표를 통과해도 중요한 결함은 남았다. **평가 항목과 실제 성공 조건의 간격이 일부 성과를 과대해석하게 만들 위험이 있었다.**

### ⑥ 3D와 학습은 실행보다 품질이 문제였음

Run 30에서는 공개 자산의 제품 버전과 스캔 품질이 광고 제작의 출발 조건을 만족하지 못했다. Run 31에서는 로컬 학습과 가중치 생성에 성공했지만, 학습된 출력의 큰 형상이 다른 제품처럼 남았다.

Run 31의 품질 저하를 특정 원인 하나로 확정할 실험은 하지 않았다. 기반 모델의 성능, 학습 사진의 배경·다양성, 200단계·rank 4 설정, 구도 제어 방식 등이 영향을 주었을 가능성은 있지만 **검증하지 않은 원인 후보**다. ‘GPU가 없어서 실패했다’거나 ‘더 학습하면 해결된다’고 결론 내릴 수 없다.

### ⑦ 빠른 탐색은 수행했지만 운영 효과를 증명할 설계까지 가지 못함

여러 유망한 접근을 작은 사례로 빠르게 시험하는 방식이었다. 대부분 표본이 작고 조건을 아는 시각 평가였으며, 일부 비교는 모델·입력 방식도 달랐다. 실제 서비스의 호출 자료와 같은 조건을 확보한 실험도 아니었다. 이는 결과를 일반화하기 어려운 이유다. 동시에 **눈에 띄는 구조 실패까지 단지 평가가 엄밀하지 않아서 생긴 것으로 돌릴 수는 없다.**

## 8. 구현 경계와 후속 검증의 질문

원래 구상은 **사진에서 제품의 사실을 정리하고, 요청에 맞는 제작 경로를 선택하며, 결과의 구조 오류를 찾아 고치는 전체 제작 시스템**이었다. 실제 구현은 개별 가설의 실험 코드와 한정된 인쇄 후처리 기능이다.

가장 큰 간극은 **새 시점과 새로운 광고 장면에서도 그 제품의 형상·부품 관계를 신뢰할 수 있게 유지하는 방법을 확보하지 못한 것**이다. 자동 요청 해석과 통합 UI가 없는 점도 미완성 요소지만, 이를 모두 연결한다고 핵심 품질 문제가 해결된다는 근거는 없다.

과제 종료 시 유지할 산출물은 실험 기록·코드·비교 자료와 JamMate 한정 시제품이다. 구도 점수 추가 조정, 작은 인쇄 튜닝, 다른 상품 인쇄 복원 확대, 2D 부품 고정 합성의 후속 작업은 중단했다. 3D는 이번에 확보한 자산 경로를 중단했고, Run 31의 SDXL LoRA 설정도 추가 튜닝·시제품 통합 없이 보관한다.

이 종료 판단은 해당 실험 조건에 대한 결정이다. 다른 자산·모델·데이터에서의 가능성이나 위 제안 A–D의 효과는 미검증으로 남긴다. 테르밋에 제안하는 것은 이 구분을 바탕으로 다음 비교를 선택하는 방식이며, 미완성 기능의 성과를 약속하는 것이 아니다.

## 공개본의 입력 자료

고객 사진·생성 결과·CS 원문·내부 링크·대화/회의 자료, 모델 가중치·캐시·외부 바이너리는 포함하지 않았다. ZIP의 이미지도 공개 권한을 별도로 확인할 수 없어 이 공개본에서는 제외했다. 일부 설정은 `LOCAL_INPUT_REQUIRED`로 치환했다.

따라서 공개본만으로 과거의 모든 비교 화면을 재현할 수 없다. 원본 자료가 필요한 코드와 웹 비교 화면은 **소스 보관** 상태다. 데이터 확보·등록·가중치 다운로드가 필요한 지점은 실행 안내에 기록했다.

검사 결과와 자료 의존 테스트의 상태는 [검증 기록](docs/validation.md), 공개 파일의 선정·변경 내역은 [공개 범위·출처](docs/publication.md)를 참고한다.
