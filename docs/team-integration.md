# 두 작업의 연결

## 기여 구분

- `research/`: 생성 절차 비교, Run 01–31, 실사 재투영·구도 선택·인쇄·부품 복원·3D 자산·상품 LoRA, JamMate 브라우저 시제품.
- `teammate/creazy-consistency/`: 팀원이 제공한 `c71a0f8` 코드 스냅샷. 기준 자료(refset), 명세(spec), 검수(check), 평가(bench), FastAPI 데모, 전체/부품/인쇄 복원 실험.
- 두 코드를 연결한 범용 시스템을 새로 구현한 것은 아니다. 결과의 논리와 코드 탐색 경로를 통합한 제출 아카이브다.

## 공통 질문별로 읽기

### 생성 절차를 바꾸면 정확해지는가?

우리 측 단계 분리·재참조·상태 관리 실험은 일반 호출 대비 추가 이점이 뚜렷하지 않았다. 팀원은 프린트 면을 입력에서 놓치지 않도록 기준 자료와 합본을 만들었다. **필요한 정보를 실제 입력에 포함하는 효과**와 **복잡한 제작 절차 자체의 효과**는 분리해야 한다. 크리에이지의 정확한 내부 호출 입력을 확보해 원인을 재현한 것은 아니다.

### 실물 픽셀을 쓰면 제품이 정확해지는가?

우리 재투영은 원본 글자·면 정보를 옮겼지만 박스의 접힘·접합은 맞추지 못했다. 팀원 선반 재투영(E1)은 세 장면의 각도 대응을 보였지만 사진에 없는 면, 자동 카메라 추정, 긴 그림자가 약했다. 전자는 미사용 목표 실사와 비교한 구조 평가이고, 후자는 장면 각도 대응의 정성 관찰이다. 서로 같은 성공률로 계산할 수 없다.

### 제품 전체를 바꾸는 것과 일부만 바꾸는 것은 다른가?

우리 골프티의 고정 레이어 합성은 이중 윤곽·접촉부 합성감이 남았다. 팀원 전체 제품 경로도 원본 디테일을 지켜도 반사·투명 재질·접촉 그림자 때문에 부자연스러웠다. 제품 픽셀 보존과 광고에서 같은 제품으로 보이는 것은 다르다.

팀원 펜 시연은 LaMa로 잘못된 심·그림자·선을 지운 뒤 원본 심을 정렬해 넣었다. 주변을 유지하면서 국소 구조를 되돌린 사례지만 수동 영역 지정과 컷별 설정이 있고 블라인드 평가 전이다. 우리 펜의 국소 길이 비율 개선도 휘어짐 해결을 입증하지는 못했다.

따라서 **작은 복원 단위가 자연스러움을 유지하기 쉬울 수 있다**는 가능성을 얻었다. 상품·구도·평가 조건이 달라 전체 교체보다 항상 좋다는 법칙은 아니다.

### 인쇄만 가져오면 어떨까?

JamMate는 큰 검은 제품명 한 줄을 원본에서 가져와 위치를 자동 추정했다. 원본 등록은 수동이고, 성공 사례는 의도적으로 제품명을 비운 생성본이다. 다른 상품은 대응점 부족으로 보류했다.

팀원 C는 장면의 저주파 조명과 원본 인쇄의 고주파 획을 결합했다. 캔에서 가능성이 있었지만 굽은 병은 합성감이 컸다. 1차 사람 평가는 평가자 1명·C 2판이었으며 최신 수정판/시연 이미지와 같은 결과로 취급하지 않는다. C 3판은 추가 평가 전이었다.

두 방식은 형태 복원이 아니다. 대응점 증가, 영역 밖 무변경, 읽히는 인쇄가 각각 다른 조건을 확인하며 고객 승인이나 전체 광고 품질을 대신하지 않는다.

## 비교하지 않는 것

- 팀원 전체 합성의 서브에이전트 판정과 사람 평가 점수를 통합하지 않는다.
- 각 팀 Run 번호와 시연 버전을 대응시키지 않는다.
- 서로 다른 상품의 픽셀/인라이어/형상 오차를 하나의 정확도로 합치지 않는다.
- 기반 모델이 잘한 결과를 추가 처리나 LoRA의 성과로 가져오지 않는다.

근거: 우리 측 최종 회고, 팀원 ZIP의 `docs/real_product_summary.md`, `docs/experiment_gates_ours.md`, `docs/work_summary.md`를 참고해 공개 가능한 서술로 재작성했다. 원본에는 고객 이미지·내부 링크가 있어 공개본에 그대로 싣지 않았다.
